# 分析与能力边界

## 适用范围

先通过可用工具取得数据或完成操作，再基于真实结果继续分析。保留官方技能中的业务场景：

| 用户任务 | 先取得的证据 | 当前会话继续完成 |
|---|---|---|
| 卡点、延期、风险诊断 | 状态、节点与操作记录 | 分析原因、风险和下一步 |
| 排期或工时分析 | 完整排期、人员与时间范围 | 判断负载和冲突 |
| 周报、待办总结 | 待办和必要的变更记录 | 生成结构化总结 |
| 图表分析 | 图表与相关业务数据 | 分析维度与趋势 |
| 当前工具不支持的操作 | 当前 schema 与已查询状态 | 说明缺失步骤，交付已验证部分 |

用户只要数据时直接交付数据。需要分析时，在当前会话完成，不自动创建外部 AI 助手跳转链接。

## 处理流程

1. 确认工具存在，按实时 schema 完成查询或操作；没有工具时不要伪造调用和结果。
2. 检查目标、时间范围和分页完整性。`query_all.summary.complete=false` 或批量存在失败项时，说明缺口；首页数量不能当全量。
3. 将观测事实、推断和建议区分清楚；未知原因不要写成已经查证。
4. 对未完成部分说明具体限制。项目未启用资源库、工时或 WBS 时，不自动修改配置。
5. 用户需要页面链接时，按 [url-links.md](url-links.md) 生成或引用已验证的业务链接。

## 原生能力与边界

- URL 解析：`lark-project__url_decode` 只提供页面类别和候选 ID，不能代替业务权限验证。
- 附件：`lark-project__attachment_upload` / `lark-project__attachment_download` 执行签名计划；上传仍需绑定并回读，详见 [attachment.md](attachment.md)。
- 批量：`lark-project__workitem_batch_get` 分别返回成功与失败，每个 ID 仅一页。
- 全量：`lark-project__query_all` 返回每页原始数据和完整性标记，详见 [performance.md](performance.md)。

原生查询编排依赖当前会话 MCP runtime，附件路径属于 Gateway 并遵守 workspace 文件策略。工具不可用时改用当前提供的官方 MCP 能力或说明缺口；不安装 CLI、临时编写替代程序或使用未提供的接口。
